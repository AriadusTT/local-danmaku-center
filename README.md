# local-danmaku-center

本地弹幕中心

**管理本地弹幕：支持从多个来源导入弹幕，经去重、清洗、时间轴校准后统一入库；播放器按本地条目读取已治理的结果。**

> 这不是「又一个 Emby 弹幕下载插件」。
> 现有插件解决的是「**取**」——从某个平台把弹幕拉下来，原样播；
> 本项目解决的是「**管**」——多源合并、清洗、校对、可追溯，最后才输出。

当前版本 **v0.7.0** · 阶段一「媒体库索引」已完成，阶段二「弹幕资产入库」进行中

---

## 它解决什么问题

现在的弹幕工具有三个共性缺陷：

1. **只有一个源**。按优先级 fallback，B 站拿不到才换弹弹play，从不合并。
2. **不做清洗**。拉下来原样播，重复刷屏、广告、引战、错别字一概不管。
3. **时间轴不校对**。不同源的弹幕对应不同视频版本，差几秒就满屏错位。

结果就是：弹幕有了，但难看。

这里的做法是把弹幕当成**资产**来管——先落库、标源，再清洗、校准，让它可以被检索、被校对、被回滚。数据先落地，治理在本地完成，输出按需发生。

## 核心能力

### 清洗流水线

| 层 | 做什么 | 典型效果 |
|---|---|---|
| L1 精确去重 | 时间取整到秒 + 文本归一化后完全相同的合并 | 去掉 60–80%（跨平台转载多为整段复制） |
| L2 近似去重 | 同文本在 ±2 秒内出现，或 SimHash 相似度超阈值 | 去掉换行、补标点后的复制 |
| L3 刷屏抑制 | 同文本超过 K 次只保留 K 条，K 随该集时长自适应 | 干掉复读机 |
| L4 内容过滤 | 广告 / 引战关键词、纯符号、超长无意义串 | 清理噪音 |
| L5 密度控制 | 同一秒超过 N 条时按权重保留 | 解决「合并后太密」这个反效果 |

每层独立开关、参数可按集调整，并且都能看到**清洗前后对比**——不是黑盒处理。

### 时间轴校准

合并的前提是同一版本：

- 为该集设置偏移量，实时预览效果
- 校准结果按 `(剧集, 季, 源)` 持久化，第二次自动套用
- 提供密度曲线对比，用 OP / 高潮段的弹幕峰值辅助人工对齐

不做全自动对齐。技术上不可靠，宁可让人确认一次，也不要让弹幕整体偏移三秒。

### 来源可追溯

合并后每一条弹幕都保留 `source`，可以：

- 按源整体开关（某个源质量差就关掉）
- 查某条弹幕来自哪里
- 回滚某次合并

既是调试需要，也是混源之后的基本防线。

## 与现有方案的区别

| | 常见 Emby 弹幕插件 | 本项目 |
|---|---|---|
| 定位 | 下载器 | 资产管理与治理 |
| 数据源 | 单源 fallback | 多源合并 |
| 去重 | 无 | L1–L5 五层 |
| 时间轴 | 不处理 | 手动校准 + 偏移记忆 |
| 来源追溯 | 无 | 每条带 `source` |
| 界面 | 插件配置页 | 独立控制台（库 / 分季 / 日志 / 统计） |
| 前置依赖 | 必须有 API 凭证 | **本地文件即可用**，凭证只是加分项 |

最后一行是关键：没有 API 也能用。导入已有的 `.xml` / `.ass` 就能开始治理。

## 数据从哪来

全部可选，任何一个源失效系统仍然可用：

| 来源 | 需要凭证 | 说明 |
|---|---|---|
| 本地文件导入 | 否 | 扫描媒体目录里已有的 `.xml` / `.ass`，或手动上传 |
| 自建弹幕库 | 否 | 用户自己维护的弹幕文件目录 |
| B 站 | 否 | 按剧名 + 集定位 cid 取 XML，无需授权但接口会变 |
| 弹弹play | 是 | 需自行申请 AppId，**项目不含任何凭证** |

## 界面

**控制台**左右两栏：

- 左侧：扫描面板（模式、进度、按库分项）+ 媒体库卡片墙（库筛选 / 搜索 / 分页）
- 右侧：入库统计 + 运行日志（跟随滚动，日志内部滚动）

卡片按「一部剧一卡」组织。同一部剧的多个季分行显示，季标签 `S1` `S2`，特别篇记作 `SP`，缺季号的记为 `—` 并排在最后。每季最多展示 16 个方块，多出的折成 `+N`；超过 3 季折成一行摘要。

方块颜色：灰=待匹配、蓝=已匹配、绿=已缓存、红=失败。

**设置页**管 Emby 连接、媒体库勾选、每页条数、定时任务，以及「完全重置 / 清空扫描数据」两个危险操作（二次确认）。

## 快速开始

需要 Python 3.11+。

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt   # Windows
.venv/Scripts/python.exe run.py
```

Linux / macOS 把 `.venv/Scripts/` 换成 `.venv/bin/`。

打开 <http://127.0.0.1:8000>，完成三步引导：

1. 填 Emby 地址 + API Key（支持 IP / 主机名 / 域名，不写协议自动补 `http://`）
2. 勾选要监控的媒体库（同步后默认全部未勾选）
3. 选择是否立即全量扫一次建立索引

> 只收录「电影 / 剧集 / 混合视频」三类库；合集、音乐、家庭视频自动忽略。
> 地址与密钥只保存在本机 `data/app.db`，不上传、不需要改配置文件。
> 服务启动时不会自动扫描，也不会主动请求 Emby。

API Key 在 **Emby 后台 → 设置 → 高级 → API 密钥** 生成。

## 配置

Emby 地址、API Key、每页条数、定时任务都在网页「设置」里改，存进数据库，**优先级高于 `.env`**。

`.env` 只放进程级参数：

| 键 | 说明 |
|---|---|
| `APP_HOST` / `APP_PORT` | 默认 `127.0.0.1:8000`，**保持只监听本机** |
| `DB_PATH` | 默认 `./data/app.db` |
| `REQUEST_TIMEOUT` | 请求 Emby 的超时秒数，默认 30 |
| `PAGE_SIZE` | 扫描分页大小，默认 500 |
| `SCHEDULER_ENABLED` | 是否启用定时扫描 |
| `SCAN_CRON_INCREMENTAL` / `SCAN_CRON_FULL` | 增量 / 全量 cron，默认每天 03:00、每周日 03:00 |
| `EMBY_BASE_URL` / `EMBY_API_KEY` | 可选兜底，正常不用填 |

复制 `.env.example` 为 `.env` 再改。`.env` 不进版本库。

## API

当前所有接口都属**管理面**（控制台与脚本使用）；给播放器读取已治理数据的**消费面**接口在阶段六实现。接口文档见 `/docs`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET / PUT | `/api/settings` | 读取 / 更新配置（密钥不回传明文） |
| GET | `/api/settings/status` | 引导阶段：`unconfigured` / `no_libraries` / `no_selection` / `ready` |
| POST | `/api/settings/test` | 测试 Emby 连通（不落库，短超时） |
| POST | `/api/settings/reset` | 完全重置（配置 + 扫描数据） |
| POST | `/api/settings/purge` | 只清空扫描数据 |
| POST | `/api/libraries/refresh` | 同步库列表并探量 |
| GET | `/api/libraries` | 库列表（只含媒体库） |
| PATCH | `/api/libraries/{id}` | 启用 / 停用某个库 |
| POST | `/api/scan` | 启动扫描 `{mode: "full"\|"incremental"}` |
| GET | `/api/scan/current` | 当前是否有任务在跑 |
| GET | `/api/scan/runs` | 历史扫描记录 |
| POST | `/api/scan/{id}/cancel` | 取消 |
| GET | `/api/media/groups` | 卡片墙数据：按剧聚合 + 分页 |
| GET | `/api/media` | 平铺条目列表 |
| GET | `/api/media/cover/{id}` | 服务端代理 Emby 海报（不暴露 API Key） |
| GET | `/api/media/stats` | 入库统计 |
| GET | `/api/logs?after=<seq>` | 增量运行日志 |

| 表 | 用途 |

## 合规与边界

本项目受「弹弹play 开放弹幕网络」2026-11-06 接入政策约束，**从设计上就避开红线**：

| 不做 | 原因 |
|---|---|
| 不镜像官方接口 | 政策第 7 条禁止 API 镜像 |
| 不向第三方提供弹幕接口 | 政策第 7 条禁止接口转发 / 二次分发 |
| 不内置任何凭证 | AppId 由使用者自行申请，仓库与镜像里都没有 |
| 不做公共实例 | 一处存储、多处分发即构成转发服务 |
| 不批量预抓全库 | 按需处理，播放哪集处理哪集 |
| 不公开发布合并弹幕包 | 弹幕内容有著作权，混源后难以溯源 |

**允许的**：本地缓存、多源合并、清洗、导出供自己使用。官方配额公告明确建议「启用本地缓存、减少重复拉取」，这些都在鼓励范围内。

边界只有一条：**数据可以落地、可以加工，但不能对外提供服务。**

因此默认 `APP_HOST=127.0.0.1`，不要改成 `0.0.0.0`。

## 路线图

### 阶段一 · 媒体库索引 ✅ 已完成

- [x] Emby 连通与配置（网页填写，存本地 DB）
- [x] 媒体库同步，识别「电影 / 剧集 / 混合」三类
- [x] 分页扫描（全量 / 增量）、按库进度、取消
- [x] 条目索引与差量（`fingerprint = sha1(path|size|runTimeTicks)`）
- [x] 卡片墙：2:3 海报 + 分季分行 + 单集方块 + 抽屉
- [x] 运行日志（内存缓冲、级别筛选、复制 / 下载）
- [x] 定时任务（增量 / 全量 cron）

**验收**：实测 2712 集 / 135 部；二次全量扫描全部 `unchanged`；取消后剩余库正确标记。

---

### 阶段二 · 弹幕资产入库（当前）

目标：让库里有真实弹幕数据可治理。**没有资产，后面的清洗都是空谈。**

- [ ] `danmaku_asset` 表：`emby_id` / `source` / `format` / `content_hash` / `count` / `imported_at`
- [ ] 扫描媒体目录已有的 `.xml` / `.ass`，解析后入库
- [ ] 手动导入：上传文件、粘贴内容
- [ ] 目录监听（可选，指定一个弹幕暂存目录）
- [ ] 覆盖率视图：哪些剧有弹幕、哪几集缺、缺多少
- [ ] 卡片方块增加第四种状态：已入库

**验收**：一部剧的弹幕能在卡片墙上显示「已入库 N 条」，点开能看原始内容。

---

### 阶段三 · 清洗流水线

按收益排序实现，先做最容易见效的：

- [ ] **L1 精确去重**（时间取整到秒 + 文本归一化）
- [ ] **L3 刷屏抑制**（同文本超 K 条截断，K 随时长自适应）
- [ ] **L5 密度控制**（同秒超 N 条按权重保留）
- [ ] **L2 近似去重**（SimHash，阈值可调）
- [ ] **L4 内容过滤**（关键词表 + 纯符号 + 超长串）
- [ ] 每层独立开关与参数面板
- [ ] 清洗前后对比视图（条数、密度曲线、被滤掉的样本）

**验收**：同一集清洗前后条数有明确下降，且肉眼观感变好；关闭某一层能完整还原。

---

### 阶段四 · 时间轴校准

- [ ] 单集偏移设置 + 实时预览
- [ ] 偏移记忆：按 `(剧集, 季, 源)` 持久化，二次自动套用
- [ ] 弹幕密度曲线对比，辅助人工对齐（OP / 高潮段峰值）
- [ ] 批量套用：同季所有集沿用同一偏移

**验收**：两源合并后无肉眼可见错位；同一季第二次打开无需重新调。

---

### 阶段五 · 多源合并

- [ ] 合并策略：并集去重 / 按源加权
- [ ] `source` 字段全链路保留
- [ ] 溯源查询：某条弹幕来自哪个源
- [ ] 按源开关，关闭后立即生效
- [ ] 合并记录 `danmaku_merge`，支持回滚

**验收**：同一集两源合并，结果可逐条追溯到来源，可一键回滚。

---

### 阶段六 · 输出

- [ ] JSON 格式定义（含 `schema_version`，字段：时间 / 模式 / 颜色 / 文本 / 来源）
- [ ] 按需导出：单集、整季、整部
- [ ] 播放器读取接口（**只服务本机**，按本地条目 ID 取已治理结果）
- [ ] Emby 插件接入，播放时加载

**验收**：插件能正常播放带弹幕的视频，且断网不影响（数据全在本地）。

---

### 阶段七 · 可选远程源

- [ ] B 站 adapter（剧名 + 集 → cid → XML）
- [ ] 弹弹play adapter（有 AppId 才启用，无凭证时该源灰显）
- [ ] 请求串行 + ≥1 秒间隔 + 429 指数退避
- [ ] 匹配结果落库，一集只查一次

**验收**：有凭证时能拉取；无凭证时系统其余功能完全可用。

---

### 明确不做

- 镜像官方接口，或提供与官方同构的搜索端点
- 公共实例（一处存储、多人连）
- 批量预抓全库
- 内置 / 打包任何 API 凭证
- 公开发布合并后的弹幕包

---

### 最短可用路径

不必按编号顺序做。想尽快看到弹幕：

**阶段二 → 阶段三（只做 L1 + L3 + L5）→ 阶段六 → 阶段二补覆盖率**

时间轴校准和跨源合并是「锦上添花」，没有它们单源也能看。先把「有弹幕 → 能看」这条最短链路打通。

## 技术栈与已知限制

FastAPI + SQLAlchemy(async) + aiosqlite(WAL) + APScheduler + Jinja2 + 原生 JS/CSS。单进程单 worker，跑在 `127.0.0.1:8000`。

- 卡片高度由海报决定，1–3 集的短剧右侧会留白
- 日志不持久化，重启清空
- 增量扫描只更新不删除，发现删除必须跑全量
- Emby 返回的是容器内路径，本机不可读，因此匹配只能走元数据 / 文件名，不能用文件 MD5
- 目前只支持单个 Emby 实例
